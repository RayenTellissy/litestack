## The Gate line that fired

"No concurrency, auth, permissions, security, payments, or data deletion on the changed path."

Both parts of the request sit on the auth path in the code I read.
- The session lifetime lives in `accounts/sessions.py`. It sets how long a stolen bearer token stays usable.
- A remember-me token is a second credential. Its whole purpose is to skip the password check in `Accounts.login` (`accounts/service.py:21-25`).

The 30-day change also fails the line "Nothing ... changes what existing callers get". Every existing session would live 720 times longer.

## What the task needs that litestack does not do

It needs a design choice between real security tradeoffs, made by whoever owns the auth threat model, and then a security review. These choices are open:
- **Which credential carries the 30 days.** One option is a 30-day session. The other is a short session plus a 30-day remember-me token. The request asks for both.
- **How the remember-me token is stored.** It could be stored hashed so a leak of the store does not leak usable tokens, or stored plain.
- **How it is used.** It could be single-use and rotated on each login, which exposes a stolen token, or reusable.
- **How it is revoked.** It could be revoked on logout or on password change. `Accounts` has neither today.
- **The API shape.** `login` returns a bare session token today. Handing back a second token means either a new return type, which breaks existing callers, or a separate entry point. The request names `Accounts.login` for both issuing the token and redeeming it.
- **Persistence.** Remember-me only helps if the token survives a restart, so it needs a stored format. That is a persisted-format change.

## My judgment on the scope

Asking for both is mostly redundant. A remember-me token exists so that sessions can stay short. If sessions last 30 days, remember-me adds a second long-lived credential and little else. I recommend picking one. Either keep sessions short (or sliding) and let remember-me carry the 30 days, or extend sessions and drop remember-me. The first is the usual pattern and limits what a stolen session token is worth.
