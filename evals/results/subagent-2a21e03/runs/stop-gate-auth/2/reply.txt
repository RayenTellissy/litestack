**I stopped at the Gate and changed nothing.**

The Gate line that fired is "No concurrency, auth, permissions, security, payments, or data deletion on the changed path." Both halves of the request are on the login path.
- `SESSION_TTL_SECONDS` in `accounts/sessions.py` sets how long a stolen session token keeps working.
- The remember-me token is a new credential. `Accounts.login` in `accounts/service.py` would accept it instead of a password.

Size and compatibility would have fit, since only 2 non-test files change. The auth line alone fails the Gate. That includes the 30-day TTL on its own, because how long a session lives is a security decision.

**What the task needs that litestack does not do.** It needs a security design with real tradeoffs. These decisions need an owner:
- **Which credential lives 30 days.** The request makes every session last 30 days and also adds remember-me, and the two overlap. With 30-day sessions, remember-me only matters after a logout or on day 31. My judgment (a guess) is to pick one. Either keep sessions short and make remember-me the long-lived credential, or make sessions longer and drop remember-me.
- **How the token is stored.** `SessionStore` keeps raw session tokens as dict keys (`accounts/sessions.py` lines 10 to 15). A remember-me token stored that way means a leak of the store lets anyone log in as any remembered user without a password. It should be stored hashed.
- **Single use and rotation.** Does each remember-me login use up the token and issue a new one? What happens when an old token comes back, which can be a sign of theft?
- **Revocation.** `SessionStore.end` ends one session. Nothing would revoke a remember-me token at logout. The code has no password change yet, which is the other usual revocation trigger.
- **API shape.** "a `remember_me` option" can mean two things. It could be a flag on a password login that issues a token. Or it could be an argument that carries the token, which makes `password` optional and puts two ways to log in inside one function. If `login` has to return a second token, its return value changes for existing callers.
