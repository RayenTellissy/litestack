Tasks can now have an optional due date. `python3 -m tasks add "Buy milk" --tag home --due 2026-11-01` saves it, and `list` shows `[ ] 1 Buy milk #home due 2026-11-01`. `list --overdue` shows only open tasks that are past due, and prints `No tasks.` when there are none. An invalid date such as `2026-02-30` makes `add` exit with status 2 and saves nothing. Older task files load as before, and tasks without a due date print and save exactly as before. The work is in two commits on `feat/due-date`. There is no PR because the repository has no remote.

**The shape and why**
- `Task` has a new last field, `due: Optional[datetime.date] = None`. A `date` rather than a string makes the overdue check a plain date comparison.
- Text becomes a `date` in two places. One is the argparse `type=` on `--due`, which rejects a bad date before anything is loaded or saved. The other is `store._decode`, which reads the file.
- The file format lives only in `store.py`, in `_encode` and `_decode`. A dated task is saved as `"due": "YYYY-MM-DD"`. An undated task is saved with no `due` key, the same way older files store it.
- The `--overdue` filter sits next to the existing `--tag` filter in `cmd_list`.
- A designer subagent sketched this shape before the build and returned no Stop.

**Needs your call** (what the change does now):
- `list --overdue --all` still shows only open tasks, because a done task is never overdue. `--overdue` combines with `--tag`.
- A task due today is not overdue, since the request says "earlier than today". "Today" is the machine's local date.
- An undated task is saved with no `due` key, so older versions of the tool can still read the file. A hand-written `"due": null` fails to load with a traceback, like other malformed files do today.
- The invalid-date error uses argparse's normal output: a usage line, then `tasks add: error: argument --due: invalid date value: '<value>'`. Bad arguments such as `done abc` already produce this kind of error.
- `--due` accepts only the exact `YYYY-MM-DD` form. If `--due` is given twice, the last one wins. `add --help` shows `--due YYYY-MM-DD` with no help text, the same as `--tag`.
- A malformed `due` in a hand-edited `tasks.json` fails with a traceback, like other malformed files.

**Principles that changed a decision**
- Model the domain and Types: `due` is a `datetime.date`, not a string.
- Boundaries: text is parsed once on the way in. A bad date fails in argparse, which is why nothing is saved. No guard in `cmd_add` is needed.
- Design it as if it was always there: `due` is an ordinary dataclass field with a default, and the overdue filter sits with the other filters.
- Smallest change: no `is_overdue` method, no injectable clock, and no new error handling for malformed files.
- Experience first: the usage line shows `--due YYYY-MM-DD`, so the expected format is visible when the user gets it wrong.
- Encode lessons in structure: the Python 3.11 format gap is covered by a test, not only a comment.
- Verifiable units: the failing tests are committed first, then the feature.
