## What you can now do

You can run `python3 -m tasks search <text>`. It prints the open tasks whose title contains the text, ignoring case, using the same line format as `list`. Adding `--all` also prints done tasks. When nothing matches, it prints `No matching tasks.` and exits with status 1. I confirmed all of this by running the real CLI against a throwaway `TASKS_FILE`.

```
$ python3 -m tasks search MiLk
[ ] 3 Oat MILK run
[exit 0]
$ python3 -m tasks search milk --all
[x] 1 Buy milk #home
[ ] 3 Oat MILK run
[exit 0]
$ python3 -m tasks search taxes
No matching tasks.
[exit 1]
```

In that run, task 2 is "Ship release" with the tag `#milk`. It is left out because only its tag matches, not its title.

## The shape I chose

- **No new data type.** A search result is just a filtered list of the existing `Task` objects. Each line is printed with `Task.line()`, the same method `list` uses, so the format can't drift from `list`'s.
- **Where it lives.** I added one function, `cmd_search`, and one `search` subcommand with an `--all` flag in `tasks/cli.py`, next to `cmd_list`. The search text is case-folded once when it comes in.
- **Docs.** The README's usage block now has a `search` example.
- **Design step skipped.** The change adds no new type, module, or function that another module calls. The existing `list` command served as the pattern to copy.
- **Size.** 3 files changed with 51 insertions. 20 of those lines are outside the tests.

## Needs your call

Each of these is one line on what the change does now:
- `No matching tasks.` goes to stdout, the same stream `list` uses for `No tasks.`. The `done` command, by contrast, prints its miss to stderr.
- When at least one task matches, the command exits 0.
- `search ""` matches every open task, so it prints the same thing as `list`.
- If the data file is missing, it counts as no match and prints `No matching tasks.` with exit 1.
- Case matching uses `str.casefold`, so `STRASSE` matches "Straße".
- Results come out in data-file order, the same as `list`.
- Search text with spaces has to be quoted. Unquoted `search buy milk` is a usage error with exit 2.
- Text that starts with `-` needs a `--` before it, as in `search -- -milk`.
- `search` has no `--tag` option, unlike `list`. The request didn't ask for one.
