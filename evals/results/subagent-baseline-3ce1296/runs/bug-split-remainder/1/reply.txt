Uneven splits now add up to the amount entered. `python3 -m tabsplit 100.00 alice bob carol` prints `Total: $100.00` instead of `$99.99`. Earlier names in the list pay the extra cents.

**What was broken.** When a bill did not divide evenly, the leftover cents disappeared. Each person's share was right to within a cent, but the shares added up to less than the bill.

**Root cause.** `allocate` in `tabsplit/money.py` floored each share with `total_cents // parts` and threw away `total_cents % parts`. I measured each stage with a probe script. `parse_amount` and `add_tip` gave the correct 10000 cents. `allocate(10000, 3)` returned `[3333, 3333, 3333]`, which sums to 9999. The repo has one commit, so this is not a regression from a later change.

**Fix.** `allocate` now uses `divmod` and gives one extra cent to each of the first `remainder` parts. Shares differ by at most a cent and always sum to the total. That holds for negative totals too.
```python
share, remainder = divmod(total_cents, parts)
return [share + 1] * remainder + [share] * (parts - remainder)
```
