Splitting a bill no longer loses cents. `python3 -m tabsplit 100.00 alice bob carol` now prints `Total: $100.00`, and the leftover cent goes to the first person listed. The fix is two commits on `fix/split-remainder`. There is no PR because the repo has no remote.

**What was broken.** Whenever the amount did not divide evenly, the receipt total came out short by up to one cent per person, minus one. $0.05 split three ways came to $0.03 (measured).

**Root cause.** `allocate` in `tabsplit/money.py` gave every person `total_cents // parts` and threw away `total_cents % parts`. A probe confirmed `parse_amount("100.00")` returns 10000 and `allocate(10000, 3)` returns `[3333, 3333, 3333]`, which loses 1 cent. Parsing, tip, and formatting were correct. `git log -L` shows the code has been like this since the first commit, so this is not a regression.

**Fix.** `allocate` now uses `divmod` and gives one extra cent to each of the first `remainder` people:
```python
share, remainder = divmod(total_cents, parts)
return [share + 1] * remainder + [share] * (parts - remainder)
```
`split_even` is its only caller, and its output is unchanged for even splits.

**Review.** One fresh reviewer reran every check and got the same results. It raised one finding, and I dismissed it.
- Dismissed. A repeated name still loses money. `python3 -m tabsplit 100.00 alice alice bob` prints `Total: $66.66` because `split_even` builds a dict keyed by name. The reviewer called this design-level. I dismissed it because it is in `bill.py`, which this change did not touch, and the change does not make it worse. I measured `Total: $66.66` on both main and HEAD. It is listed below as an open item.

**Principles that changed a decision.**
- Fix root causes. I fixed `allocate`, where the cents are first lost. I did not make `receipt` print the amount entered in place of the sum of the shares, because that would hide shares that do not add up.
- Test behavior. The `allocate` test checks the sum, the count, and the spread across totals from -101 to 10001 and 1 to 7 people. It does not check an exact list, so it keeps passing if the order of the extra cents changes. The receipt test pins the output users see.
- Smallest change. I left the repeated-name bug out of this fix. It has a different cause and needs a product decision.
- Verifiable units. The failing tests are committed before the fix.
