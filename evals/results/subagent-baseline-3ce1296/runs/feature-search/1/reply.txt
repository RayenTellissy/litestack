## What you can do now

`python3 -m tasks search <text>` lists the open tasks whose title contains `<text>`, ignoring case. The output format matches `list`. `--all` adds done tasks, and it works before or after the text. When nothing matches it prints `No matching tasks.` and exits 1. It matches titles only, not tags. It never writes `tasks.json` (measured, the file's hash is the same before and after every search in the drive run). The README now has two `search` examples. The existing commands behave as before (measured, the 4 existing tests pass).

## Shape

No new data. A search is a filter over the stored `Task` list in stored order. First it applies the same open-or-`--all` rule `list` uses, then a `casefold()` substring test on the title. Each match prints through `Task.line()`, so the format cannot drift from `list`. The visibility rule moved into one function, `visible(tasks, include_done)` in `tasks/cli.py`, and `cmd_list` and the new `cmd_search` both call it. Without that, the done-visibility rule would sit in two places. The change spans 3 files and adds 46 lines (22 in `tasks/cli.py`).

## Open decisions

- `No matching tasks.` goes to stdout, like `list`'s `No tasks.`. It does not go to stderr like `done`'s `No task N.`.
- Case matching uses `casefold()`, not `lower()`.
- An empty query `search ""` lists every visible task and exits 0 (measured).
- `search` has no `--tag` option, because the request did not ask for one.
- The text is one positional argument, so a multi-word query needs quotes.

## Principles that changed a decision

- **Design it as if it was always there.** The done-visibility rule got one home in `visible()`, instead of a copy inside `cmd_search`.
- **Verifiable units.** The extraction shipped as its own refactor commit, checked by the existing tests, before the feature commit.
- **Test behavior.** The tests run the real CLI as a subprocess and check exact stdout and exit codes. The no-match test searches for a tag word to prove only titles are searched.
- **Smallest change.** No `--tag` on search, no shared argparse parent for the two `--all` flags, and no type hints the file does not already use.
- **Prove it works.** The drive script checks that search leaves `tasks.json` byte-identical.
