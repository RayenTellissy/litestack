You can now run `python3 -m tasks search <text>` to find open tasks by title, with case ignored. The output uses the same lines as `list`. `--all` also includes done tasks, and the flag works before or after the text. When nothing matches, the command prints `No matching tasks.` and exits 1. Whoever maintains this next gets one new handler, `cmd_search`, in `tasks/cli.py`, plus one subparser and five CLI tests. It follows the same `cmd_*` and `set_defaults(run=...)` pattern as the other commands.

**Shape.** No new type, and `tasks.json` is untouched. The inputs are argparse's `text: str` and `all: bool`. The rule is one predicate in the handler: `(args.all or not t.done) and text.casefold() in t.title.casefold()`. Matches come out in stored order, each printed with `Task.line()`. That keeps the format identical to `list` by construction. The filter lives in the handler because `cmd_list` keeps its filters there, and it has one caller. **Open decisions.** I made these calls myself, and each is cheap to reverse.
- `No matching tasks.` goes to stderr. Your request did not name a stream. `done` already pairs exit 1 with stderr, and this keeps stdout to matching lines only.
- Case matching uses `casefold()`, not `lower()`, so non-ASCII titles also match regardless of case.
- Only titles are searched. `search home` does not match a task tagged `#home`.
- `search ""` lists every open task and exits 0. There is no special case for an empty query.
- A query of more than one word needs quotes. Without them, argparse rejects it with exit 2.
- `search` has no `--tag` option, since none was asked for.
- The "open unless `--all`" rule is now one expression repeated in `list` and `search`. It stays that way until a third command needs it.
