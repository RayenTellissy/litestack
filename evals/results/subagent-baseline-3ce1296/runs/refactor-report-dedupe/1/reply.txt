The three summaries now share one implementation, and their output is unchanged. Callers of `daily_summary`, `weekly_summary` and `monthly_summary` see nothing different. From now on, a change to grouping, totals or the table format is one edit instead of three matching ones. There is no PR because the repository has no remote. The work is one local commit.

**What changed**
- The grouping, per-category totals and table formatting moved into one private function, `_summary(entries, period_key)` in `ledger/reports.py`.
- Each public function now passes only how a date maps to its period:
  - daily uses `day.isoformat()`.
  - weekly uses a nested `iso_week` that builds the ISO year and zero-padded week.
  - monthly uses `f"{day.year}-{day.month:02d}"`.
- Public names, signatures and `parse_line` are untouched.

**Pin**
- Before any edit, I wrote `.pin/compare_reports.py`. It loads `ledger/reports.py` from `main` with `git show` and runs the old and new versions of all three functions on 315 inputs. It compares the exact output strings, or the exception type and message.
- The inputs include:
  - the test entries, empty input, and generators (input still read once)
  - unsorted input, wide values, and a `datetime` as the day
  - ISO year boundaries (2020-12-31 and 2021-01-01 both group as `2020-W53`)
  - years below 1000, where keys sort as plain strings
  - a summation-order case (prints `0.30` as written, `0.00` if summed in sorted order)
  - error paths (a bad day still raises before a bad amount)
  - 300 seeded random lists
- The 5 existing unit tests also cover the contract.

**Equivalence proof (measured)**
- Before the edits, the pin made 945 comparisons with 0 mismatches. It also passed after each of the three edits, one per function, and after the last edit.
- `diff .pin/outputs_before.txt .pin/outputs_after.txt` prints nothing, so the 945 recorded outputs match exactly.
- `python3 -m unittest discover -s tests` ran 5 tests, all OK.
- There is no CLI or UI. The pin calls the public functions directly, and those functions are the whole surface.

**Reader load**
- Before, a reader had to compare three 17-line copies to find the one line that differed in each.
- Now there is one 17-line body and three short functions that each state their period rule.
- The file went from 65 to 42 lines. The diff is 12 insertions and 35 deletions (measured). There is one new call layer.

**Principles that changed a decision**
- Smallest change and Model the domain: the only thing that varies is a date-to-key function. So `_summary` takes that function, not a period name or a lookup table.
- Subtract before you add: I left `parse_line`'s local import alone instead of tidying it.
- Prove it works: I loaded the base module straight from `main` so the reviewer could rerun the comparison. That sent the pin past the existing tests into float summation order and which error raises first.
- Design sketch: I kept `lambda day: day.isoformat()` rather than `date.isoformat`, so a `datetime` day prints as before. I kept the f-strings rather than `strftime`, which pads years below 1000 differently on some platforms.
