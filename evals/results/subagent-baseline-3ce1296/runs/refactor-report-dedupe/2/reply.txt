## Result
Code that calls `daily_summary`, `weekly_summary`, or `monthly_summary` sees no change. Every output and every raised exception matches `main` across 15084 recorded calls (measured). Changes to grouping, totals, or the table format now happen in one place, `_summary` in `ledger/reports.py`, not three.

## Structure that changed
- One private function, `_summary(entries, period_of)`, now does the grouping, the per-category totals, the empty case, and the table.
- Each public function passes in only its period key. Daily and monthly use a lambda. Weekly uses a nested `week_of` because it has to unpack `isocalendar()`.
- Names, signatures, and `parse_line` are unchanged. The file went from 65 to 41 lines (measured).

## Pin
- `python3 -B -m unittest discover -s tests` ran after the last edit. 5 tests passed in about 0.06 s.
- The existing tests check one input per report and an empty input only for daily. So I added `.pin/record_outputs.py`. It records each report's output, or the exception it raises, for 2514 cases. Each case runs once as a list and once as an iterator.
- The cases cover ISO week year boundaries, years 1 and 9999, long and empty categories, int and negative amounts, and floats where summation order changes the result. They also include 500 random lists with 1 to 3 bad entries injected.
- I checked that the summation-order cases actually catch a change. My first pick did not, since both orders gave 4.00. I replaced it with `1e16, 1.0, 1.0`. The two orders then give 10000000000000000.00 and 10000000000000002.00 (measured).

## Equivalence proof
- `before.txt` was recorded from `main`'s `ledger` package, extracted to `.pin/main` with `git archive`. `after.txt` was recorded from the final commit.
- `diff` between them exits 0. All 15084 outputs match, and 2904 of them are raised exceptions.
- The pin does catch real differences. Against my first build it reported 540 differing lines, all of them exceptions.

## Reader-load delta
Before, a reader had to compare three 17-line bodies to see that only the key line differed. Now each report shows only its key, in 1 to 4 lines, and the shared logic is one 15-line function. The cost is one extra call into `_summary`. It is more than a pass-through because each report supplies its own key rule.

## What shipped and what I reverted
- One commit shipped.

But when an input had more than one bad entry, a different exception fired. `_summary` now does the steps in the old order. It groups first, then totals each period inside the sorted output loop.

## Principles that changed a decision
- Prove it works. The pin became a scripted diff with its output kept. The weak float case was replaced. The baseline was re-recorded from `main`'s code once the pin grew.
- Verifiable units. I built in two steps and ran the pin after each, first daily, then weekly and monthly.
- Model the domain. The only part that differs is a key function of `day`, so each report states only its period rule.
- The rule to pick the option closest to existing behavior settled the error-order question in favor of the old order.
