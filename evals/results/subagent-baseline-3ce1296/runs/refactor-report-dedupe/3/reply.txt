`daily_summary`, `weekly_summary` and `monthly_summary` now share one helper, and their output is unchanged. I checked that on 1,221 recorded outputs, which matched `main` byte for byte. There is no PR because the repo has no remote. The work is one commit, `fc88a68`, on branch `refactor/report-summaries`.

**What changed in `ledger/reports.py`**
- A new private function, `_summary(entries, period_of)`, does the grouping, category totals, row layout and the "No entries." case.
- Each public function keeps its name and signature. It only supplies its period key: `day.isoformat()` for daily, a small `iso_week` function for weekly, and `f"{day.year}-{day.month:02d}"` for monthly.
- `_summary` builds per-period category totals in a single pass instead of storing lists of entries and totalling them afterwards. It still reads the input once, so a generator works.
- `parse_line` and `ledger/entries.py` are untouched.
- `tests/test_reports.py` gains one test, described below.

**How I checked the output didn't change**
- The existing tests cover only one dataset and test the empty case for daily only. So before editing I wrote a script, `.pin/record_summaries.py`, that runs all three functions on 407 inputs. That gives 1,221 outputs, saved from `main` as `.pin/before.txt` (63,402 lines).
- The inputs include empty lists, tuples and generators, one-shot generators, ISO week-year boundaries, years 1, 9 and 999, long and unicode category names, negative amounts, and one case where the total depends on the order the floats are added in.
- I made the change one function at a time and ran the script and tests after each step.
- At the final commit, the script's output still matches `.pin/before.txt` exactly, and all 6 tests pass.
- I checked the script isn't blind to subtle changes. A version that adds the total in sorted category order produced 50 differing lines. The reviewer separately confirmed that `before.txt` really is `main`'s output.
- There is no linter or type checker in the repo, so I only checked that the file parses.

**Easier to read**
- The file drops 24 lines. Each original function was a 17-line copy, and the loops go from 9 to 3. The empty-case check goes from 3 copies to 1 and the row format string from 6 to 1.
- The cost is one extra hop from each public function into `_summary`.
- Nothing was reverted. There was no dead code to delete first.

**Review findings**
- Fixed: I had left a comment telling readers not to add up the total in sorted category order, which would change the printed float. I replaced it with the new test, `test_total_sums_in_first_seen_category_order`. It passes against `main`'s code and fails against the sorted-order version.
- Dismissed: the reviewer showed that inputs which aren't proper `Entry` values can behave differently.
  - One case is a generator that yields the same mutable object over and over, which now prints different totals.
  - The other is entries with bad field values, which still raise an error but a different one (for example `TypeError` instead of `AttributeError`).
  - No caller can produce either case. The only callers are the tests, which pass frozen `Entry` objects, and `parse_line` always builds `Entry(date, str, float)`.
  - A frozen `Entry` can't be changed after it is yielded, and nothing catches those exceptions.

**Principles that changed a decision**
- **Model the domain:** the shared helper keeps running totals per period and category directly, which removed the second loop over stored entries.
- **Encode lessons in structure:** the sum-order rule is now enforced by a test rather than a comment.
- **Prove it works:** I wrote the recorded-output script before any edit and checked it would catch a subtle change.
- **Smallest change:** I left `parse_line`'s local import alone, and there are no separate grouping, totals and formatting helpers.

**Open items**
- The "output unchanged" claim covers well-formed entries, meaning any `Entry` and any record whose fields don't change after it is handed over. For malformed records it does not hold, as described above.
- `.pin/` is untracked and not committed. It holds `record_summaries.py`, `before.txt`, `after.txt`, and `run_test_against.py` (the script that ran the new test against `main` and the sorted-order version). Delete the folder when you're done with it.
