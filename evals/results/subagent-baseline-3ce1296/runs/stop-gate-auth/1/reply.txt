## Why I stopped
The Gate line that fired bars auth and security on the changed path. Both parts of your request are on it.
- The 30-day lifetime means changing `SESSION_TTL_SECONDS` in `accounts/sessions.py`. `SessionStore.user_for` uses that value to decide whether a token still logs someone in.
- `remember_me` adds a second credential that logs a user in without a password. That is a new way to authenticate.

This needs a security design with real tradeoffs and a sign-off from whoever owns auth. Litestack does not make that call. The decisions it needs are listed below.

## Decisions for the auth owner
1. **Is `remember_me` needed at all?** I'd push back on it. A 30-day session already fixes the hourly logout. A remember-me token would be a second 30-day credential that gives users nothing extra unless sessions stay short or start expiring after a period of inactivity. I'd ship the TTL change alone (guess, not measured).
2. **Storage.** `SessionStore` keeps sessions in a dict keyed by the raw token (`accounts/sessions.py` lines 10 and 14). A remember-me store built the same way would hold usable credentials in plain form. Storing a hashed selector and validator pair avoids that.
3. **Persistence.** The dict lives in process memory, so a restart logs everyone out (inferred from the code, not run). A remember-me token stored the same way would be lost on restart too, which defeats its purpose.
4. **Rotation and theft.** Decide whether each use replaces the token. Also decide whether reusing an old token revokes the user's other tokens.
5. **Revocation.** `SessionStore.end` ends one session, but nothing in `Accounts` calls it. There is no logout or password change to hook token revocation into.
6. **Expiry policy.** Today expiry is fixed when the session is created (`create` sets `expires_at` once). Decide between a fixed 30 days and an inactivity timeout that resets on each use.
7. **API shape.** `login(username, password)` returns one token today. A `remember_me` option needs either a second return value or a second method. Making `password` optional puts two kinds of credential behind one signature. Changing the return type would also change what existing callers get, which a second Gate line bars.
