**What you can do now**
- `add <title> --due YYYY-MM-DD` saves a due date with the task.
- `list` shows the date at the end of the line, as in `[ ] 2 Pay rent #home due 2026-10-01`. Tasks with no date print exactly as before.
- `list --overdue` shows only open tasks whose date is before today. It prints `No tasks.` when none are overdue. A task due today doesn't count.
- A bad date stops `add` with exit code 2. For example, `--due 2026-02-30` prints `tasks add: error: argument --due: invalid date '2026-02-30', expected YYYY-MM-DD` to stderr. The task file stays byte for byte the same (checked with `cmp`).
- Old task files still load. I tested a file in the old format: it listed fine, and I added a dated task to it.

**Shape I chose**
- A task has one new field, `due`. It holds a real calendar date or nothing, never a plain string.
- Text becomes a date in only two places: where `--due` comes in, and where the file is read. Everything in between works with real dates.
- "Overdue" is worked out on the spot by `Task.overdue(today)`. Nothing is stored that could go stale.
- In the file, a dated task gets `"due": "2026-11-01"`. An undated task gets no `due` key, the same shape as before.
