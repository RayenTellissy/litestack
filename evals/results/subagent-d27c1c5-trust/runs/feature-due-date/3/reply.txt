- Old task files load and work with every command. After `done`, an old file is re-saved byte for byte in its old form.

**How it's built**
- The task now has an optional due date stored as a real date, not text. That makes "earlier than today" a plain date comparison.
- Date text is turned into a date in only two places: when the `--due` option is read, and when the task file is loaded. Since a bad date is caught while the options are read, `add` exits before it ever touches the file.
- In the file, a task with no due date simply has no `due` key. That is how every old file already looks, so old files need no special handling.
- The `--overdue` filter sits next to the existing `--tag` filter in `list`. The change is 5 files, 88 lines added and 5 removed.

**Open decisions**
- **Mixing old and new versions:** older versions of the tool cannot read a file once any task in it has a due date. They fail with `unexpected keyword argument 'due'`. Files where no task has a due date stay readable by older versions.
- **Date format:** `--due` accepts only the exact `YYYY-MM-DD` form. `20261101` is rejected, even on newer Python versions that would otherwise accept it.
- **Combining options:** `list --overdue --all` still shows only open tasks, because the request says open tasks only. `list --overdue --tag X` applies both filters.
- **Due today:** a task due today is not overdue. "Today" is the computer's local date.

**Principles that changed a decision**
- **Model the domain:** the due date is a real date, not text.
- **Boundaries:** date text is checked when the option is read and when the file is loaded, and nowhere else. This is why a bad date exits before anything is stored.
- **Design it as if it was always there:** "no due date" means no key in the file, so old files load the normal way.
- **Smallest change:** the overdue filter lives inline next to the tag filter. Tests use dates relative to today instead of adding a way to fake the date.
