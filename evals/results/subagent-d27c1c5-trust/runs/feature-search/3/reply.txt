All four parts of the request work: case-insensitive title search, the `list` output format, `--all`, and the "No matching tasks." message with exit status 1.

**What you can do now**
- `python3 -m tasks search milk` lists the open tasks whose title contains "milk", in any case. Each line looks exactly like a `list` line. `--all` also shows done tasks, and works before or after the text.
- When nothing matches, it prints `No matching tasks.` and exits with status 1. That includes when the task file doesn't exist yet. Searching doesn't create the file.
- Measured on the real command line:
  - `search MILK` printed `[ ] 3 Oat MILK #shop` and exited 0. The done "Buy milk" was left out.
  - `search milk --all` printed `[x] 1 Buy milk #home` and `[ ] 3 Oat MILK #shop`.
  - `search groceries` printed `No matching tasks.` and exited 1.
- The README's usage block has a new `search` example.
- For whoever maintains this next: there is one new handler, `cmd_search`, and one new subcommand entry in `tasks/cli.py`. Both sit right after `list`'s and follow the same pattern.

**How it's built**
- No new data type or stored field. Search is a filter over the tasks already loaded, keeping their order, and each match prints with the existing `Task.line()`.
- A match needs two things: the task is open (or `--all` is on), and the title contains the text, compared with Python's `casefold()`.
- I skipped the design step because nothing new crosses a module boundary. `cmd_list` stood in as the model, and the code copies its shape.

**Decisions to check**
- **Where the no-match message goes.** `No matching tasks.` goes to the normal output, like `list`'s "No tasks." The CLI's other exit-1 message (`done` with an unknown id) goes to the error output. The request says "prints" without saying which, and someone redirecting output would notice the difference.
- **No `--tag` on search.** `search` takes no `--tag` option, because the request doesn't ask for one. Adding it would be a two-line copy of `list`'s filter.
- **Unicode case matching.** Matching uses `casefold()`, so `search STRASSE` finds "Straße fegen". A plain `lower()` would miss that.
