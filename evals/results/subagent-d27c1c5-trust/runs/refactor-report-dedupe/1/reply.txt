**What changed**
- `ledger/reports.py` has a new private function, `_summary(entries, period_of)`. It groups the entries by period, adds up each category, and builds the table.
- Each public function now supplies only its own period label: the full date, the ISO week (`YYYY-Www`), or the month (`YYYY-MM`).
- The empty-input check now looks at the groups instead of the finished lines. The result is the same, because every group writes at least a header and a total line.
- One file changed, with 16 lines added and 40 removed.

**Principles that changed a decision**
- **Prove it works.** I scripted a 312-case comparison against `main` and showed it can fail, instead of trusting the 5 tests alone. It is also why the daily label still calls `day.isoformat()` rather than `date.isoformat`. The recording shows that a `datetime` day prints the full timestamp in the daily report, and `date.isoformat` would have shortened it to the date.
- **Model the domain.** The only real difference between the three functions is how a date becomes a period label. So `_summary` takes that one rule and nothing else.
- **Smallest change.** The three public functions stay as thin wrappers. There is no lookup table of periods, no new module, and no unrelated cleanup of `parse_line`.
- **Reader load.** The week label stays as a small function inside `weekly_summary`, so each report's label rule sits in the report that uses it.
