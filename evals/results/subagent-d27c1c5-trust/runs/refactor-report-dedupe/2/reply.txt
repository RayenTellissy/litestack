**Principles that changed a decision**
- *Model the domain* and *Design it as if it was always there*: only the period key differs between the three reports. So the shape is one builder that takes a key function, rather than a `period` string checked in an if-chain.
- *Smallest change*: I kept the three public functions and added no new public `summary(period=...)`, which would have given callers two ways to do the same thing. I also moved the loop body word for word instead of tidying it.
- *Prove it works*: two tidier versions would have changed the output, and I checked both.
  - The unbound `date.isoformat` instead of `lambda day: day.isoformat()` prints `2026-03-02` where the current code prints `2026-03-02T09:30:00` when a day is a datetime.
  - Summing the totals in sorted category order prints `0.00` where the current code prints `1.00` for totals {b: 1e16, c: -1e16, a: 1.0}.
